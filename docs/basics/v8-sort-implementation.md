# Array.prototype.sort 在 V8 的实现机制


### 长度决定算法

V8 的 sort 实现会根据数组长度走两条路：

- **长度 ≤ 10**：插入排序。小数组上插入排序的常数开销最小，比快排反而快。
- **长度 > 10**：快速排序，V8 7.0 之后换成了 TimSort。

这个阈值在早期 V8 版本里是 10，不同版本可能有微调，但核心思路不变：**小数据量用简单算法，大数据量用高效算法**。

### 早期的快排实现（V8 7.0 之前）

```js
// V8 内部的大致逻辑
function sort(arr, comparefn) {
  if (arr.length <= 10) {
    insertionSort(arr, comparefn)
  } else {
    quickSort(arr, comparefn)
  }
}
```

用插入排序处理 10 个以下元素的理由是：插入排序不涉及递归调用、不需要分配额外内存，在小数组上实际跑起来比快排的开销还小。

### TimSort（V8 7.0+）

2018 年 V8 把 sort 换成了 TimSort。TimSort 是 Python 里用了很多年的混合排序算法，结合了归并排序和插入排序：

1. 先把数组分成若干个已经有序的 "run"
2. 每个 run 用插入排序微调
3. 最后用归并把 run 合并起来

TimSort 在数据部分有序时性能极好，而实际开发中数据经常是部分有序的（比如按时间插入的用户列表）。

```js
// 部分有序场景下 TimSort 接近 O(n)
const arr = [1, 2, 3, 7, 8, 9, 4, 5, 6]
arr.sort() // TimSort 识别出两个 run：[1,2,3,7,8,9] 和 [4,5,6]，归并一下就好
```

### 自定义比较函数的注意事项

```js
// 错误：compareFn 必须返回数字，不能是布尔值
[3, 1, 2].sort((a, b) => a > b) // 这是错的！

// 正确
[3, 1, 2].sort((a, b) => a - b) // [1, 2, 3]
```

另外 `compareFn(a, b)` 必须满足：如果 `a === b`，返回 0。不满足这个条件的话，不同浏览器/不同 V8 版本排序结果可能不一致。
