# Vue3 渲染原理

### 编译时：模板 → render 函数

你写的 `<template>` 不是直接跑在浏览器里的。Vue3 在构建阶段会把它编译成 render 函数，这个过程做了两个关键优化：

**静态提升（Static Hoisting）**：模板里那些不会变的节点——比如 `<h1>博客标题</h1>` 这种没有插值表达式、没有动态属性、没有事件绑定的纯静态内容——编译时直接被拎出来变成常量。渲染时不需要重复创建这些节点。

**Patch Flag（静态标记）**：每个动态节点打上标记，告诉运行时"这个节点的哪部分会变"。比如 `<p :class="cls">{{ text }}</p>` 会被标记为 CLASS + TEXT。Diff 的时候只比较标记了的部分，跳过静态内容。

### 运行时：虚拟 DOM

初次渲染时，执行 render 函数生成虚拟 DOM 树，然后调用原生 DOM API 逐一创建真实元素，挂载到 `#app` 上。

同时进行依赖收集：当模板里引用了 `count.value` 时，触发 Proxy 的 get 拦截。Vue3 的依赖收集最小单位是**组件**——不是单个变量，而是一个组件对应一个副作用函数。

### 响应式更新：精准触达

当 `count.value` 改变时，触发 Proxy 的 set 拦截。Vue3 能找到是**哪个组件**用了这个数据，然后重新执行那个组件的 render 函数，生成一棵新的虚拟 DOM 树。

新树和旧树进行 Diff，结合编译阶段的 Patch Flag，Vue3 只更新真正变动了的 DOM 节点，静态节点完全跳过。

### 一张图串起来

```
写模板 → 编译(静态提升+Patch Flag) → render函数 → 虚拟DOM → 真实DOM
                                                         ↑
响应式数据变化 → set拦截 → 找到依赖组件 → 重新render → Diff → 精准DOM更新
```
