# Vue3 为什么比 Vue2 快

### 响应式系统：按需代理 vs 全量递归

Vue2 初始化时会对 data 里所有属性递归执行 `Object.defineProperty`，无论你用不用这个属性。一个深层嵌套的大对象，初始化成本相当可观。

Vue3 的 `Proxy` 是懒代理——只有当你真正访问到某个属性时，才会对它的子属性做代理。初始化时不再需要递归遍历整棵树。

### 虚拟 DOM Diff：只遍历动态节点

Vue2 的 Diff 是整棵虚拟 DOM 树全量对比，即使 90% 的节点是静态的。Vue3 在编译阶段把动态节点单独抽成 Block Tree，Diff 时跳过所有静态子树。

这跟直接操作 DOM 有什么区别？有人会想"那我直接改 DOM 不更快？"——不行。绕过 Vue 直接操作 DOM，下一次响应式更新时你的手动修改很可能被覆盖。Vue 的 Diff 保证了 DOM 状态和数据状态的一致性，Vue3 只是让这个一致性保障的成本降到了最低。

### Patch Flag：精准到属性维度的更新

Vue3 给每个动态节点打上标记，精确到"这个节点只有 class 会变"或"这个节点只有文本会变"。Diff 时：

- 标记了 CLASS 的节点，只比对新旧 class，跳过其他属性
- 标记了 TEXT 的节点，只比对文本内容
- 什么都没标记的静态节点，直接跳过

相比之下，Vue2 的 Diff 需要全量比对节点的所有属性和子节点。

### Diff 算法本身：双端对比 + 最长递增子序列

Vue2 和 Vue3 都做同层比较（不跨层级），但 Vue3 在 Diff 数组子节点时加入了**最长递增子序列（LIS）**算法，能找出哪些节点原地不动就行，哪些才需要移动。这个优化在大列表更新场景下效果显著——节点变动越多，LIS 省下的操作就越多。

### 打包体积也更小

Vue3 用 ES Module 输出，支持 Tree-shaking，没用到的 API（比如 `Transition`）打包时直接被剔除。加上核心逻辑重写后更紧凑，同样功能代码量更少，体积自然更小。
