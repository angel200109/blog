# Vue 模板编译流程

### 完整流水线

把一段模板字符串变成页面上能看到的真实 DOM，Vue 内部要走过六道工序：

```
模板字符串 → AST → 标记静态节点 → render 函数 → 虚拟 DOM → 真实 DOM
```

### 每一步做了什么

**1. 模板 → AST（抽象语法树）**

编译器用正则+状态机解析模板，把 `<div><p>{{ msg }}</p></div>` 转成一棵树状结构。每个节点记录自己的标签名、属性、子节点、指令等信息。

**2. AST → 优化标记**

Vue3 在这一步遍历 AST，标记出哪些节点是纯静态的（没有 `{{ }}`、没有 `v-if`、没有 `:class` 等动态绑定）。这些节点后续 Diff 时直接跳过，零开销。

**3. AST → render 函数**

把优化后的 AST 转成一串 JS 函数调用，比如 `h('div', null, [h('p', null, ctx.msg)])`。这就是 render 函数的本体。

**4. render 函数 → 虚拟 DOM**

组件初始化或更新时，执行 render 函数，返回一棵虚拟 DOM 树——一个轻量的 JS 对象，描述页面应该长什么样。

**5. 虚拟 DOM → 真实 DOM**

首次渲染时，遍历虚拟 DOM 树，调用 `document.createElement`、`element.setAttribute` 等原生 API，生成真实节点，挂载到容器上。

**6. 更新时：Diff → Patch**

数据变了，render 重新执行，生成新虚拟 DOM 树。新旧两棵树用 Diff 算法比较（Vue3 是双端对比 + 最长递增子序列），算出最小更新操作，只改动了的部分。

### 编译是"提前做功课"

核心思路是把能提前算的都在编译阶段算好，运行时就能少做无用功。静态节点编译时识别好了，运行时就不用再一个个比对了——这就是 Vue3 比 Vue2 快的一个重要原因。
